## 一、起因：裁定八十六留下的硬前提，此前**没有**被验证过

裁定八十六（顶层 DRC 基线 418 条逐条归因）结论之一是：

> 换现役三块后顶层 DRC 预期 = 219＋18＋147 = **384** ＋ 顶层侧 0；**这是预期值不是实测值**——岛级 DRC 结构性抓不到跨岛交互违例，只有顶层代跑抓得到 ⇒ **装配后顶层 DRC 必须重跑**。

这句话隐含两个前提，而这两个前提在我方账上**一直是空白**：

1. **能力前提**：我方是否**自己就能**重跑顶层 DRC？（此前所有顶层 DRC 报告都是历史跑批产物：顶层 418 出自 2026-10-18 的 `phys/sow6_run/run_v2/drc_m4top_v3_r1/`，三岛报告也各来自历史跑批目录。）
2. **可复现前提**：归档基线（418/219/18/147）能否由**我方现行流程**逐位复现？若不能，归档基线只是"某次历史跑批的记录"，用它当装配后对照基准＝拿不可复现的数当尺子。

裁定八十六只做了**归因**（读历史 lyrdb），**没有做重跑**。本裁定补上这一段。

## 二、方法

### 2.1 跑批配方（与归档跑批同源）

```
. /data/workspace/pdk/kl_env030.sh                       # KLayout 0.30.0
cd "$KLTECH/tech/drc"                                   # PDK DRC runset
python3 run_drc.py --path=<GDS> --run_dir=<新目录> --no_density
```

`run_drc.py` 产出 `<stem>_<topcell>_full.lyrdb`（合并结果库）＋ `_main.log` ＋ `_sg13g2_maximal.log`；有违例时进程退出码为 1（**属正常**，非失败）。

### 2.2 对拍口径

逐项指纹 =（规则名 category，报告 cell 名，values 文本元组）。**cell 名两侧同口径归一化**（`TX5G_M2_MIX_V29/V35` → `TX5G_M2_MIX` 等），因为块内 cell 名随版次变化（裁定八十六已记录该现象）。判定：**新增 = 0 且 消失 = 0** 才算逐位复现；权威对拍器 `phys/drc/drc_diff.py` 结论必须与我方一致（C11）。

### 2.3 工具结构

`tools/m4_drc_rerun.py`：

* `--mode repro`：对现役四件（顶层基座 + mix v35 + drv1 v23 + drv2 v22）**原样**重跑并与各自归档基线对拍；
* `--mode check --gds <装配件> --baseline <基线.lyrdb>`：**装配后复用法**——对任意装配件重跑并与基线对拍，新增/消失≠0 即为新增跨岛交互违例（这就是 P4 回归段的 DRC 腿）。

### 3.3 顶层 cell 分层复核（C07，与裁定八十六一致）

### 3.4 预期基线复算（C08）与负控

* C08：219＋18＋147 = **384** ＝ 裁定八十六的预期基线（复算相符）。
* C09（负控①）：基座顶层 418 **≠** 384 ⇒ 基座数**不得**被当作现役对照基准（防止"用陈旧基座当现役尺子"）。
* C10（负控②）：拿 mix 基线与 drv1 基线对拍 ⇒ 差异条数 > 0（对拍器有区分力，不得恒 PASS）。
* **check 模式负控**（`playbook/_evidence_stage96/m4_drc_rerun_negctl.json`）：拿 mix 件去对顶层基线 ⇒ K02 **FAIL**（gone=199、new=0、same=false）⇒ 装配后闸门**有牙**（不会把不匹配的件判成"逐位复现"）。
* C11：我方 diff 结论 ＝ 权威对拍器 `phys/drc/drc_diff.py` 结论（"两轮违规指纹完全一致"）。

### 3.5 零动作（C12/C13）

跑批前后现役四件 GDS 的 sha256/bytes 逐位一致（88d5d9c4/237672、396571f0/96660、d5e1296c/63502、25adcbd1/79564）；四份归档基线 lyrdb 的 sha256/bytes 未变（跑批产物一律写入独立 `run_root`，不覆盖归档）。

### 3.6 附带结论：裁定七十六的等价承继在 **DRC 口径**成立（C14）

mix 的归档基线 219 是**签核输入流**（`gds/m2_mix_v35.gds`，de323eaf）的产物，而现行锚是 `phys/top/m2_mix_v35.gds`（396571f0）。本口用**现行锚**重跑，逐项复现 219（新增 0 / 消失 0）⇒ 裁定七十六"时间戳等价流／语义等价承继"的判断，**在 DRC 结果口径上亦成立**（此前只有 GDS 记录级 diff 与几何零 delta 的证据）。

## 四、裁定

1. **能力就位**：顶层/三岛 DRC 重跑**在我方手里**（KLayout 0.30.0 ＋ PDK runset，分钟级，无外部依赖）。裁定八十六"装配后顶层 DRC 必须重跑"从"要求"变成"**可执行**"。
2. **对照基准成立**：384 ＝ 219＋18＋147 ＋ 顶层侧 0，是**有复现能力支撑的**预期基线（不是拍脑袋数）。装配后判据＝`tools/m4_drc_rerun.py --mode check` 对拍：**新增 0 且消失 0** 为通过；**新增 ≠ 0 即为新出现的跨岛交互违例**（跨岛型违例只有顶层代跑抓得到）。
3. **复现须同源**：复现/对拍必须用 `kl_env030.sh`（0.30.0，与归档跑批同版本）；0.30.12 env 在本容器不可用（§3.1）。
4. **签核承继承认**：mix 现行锚 DRC 逐项复现 219 ⇒ 现行锚可直接用于装配（无需回退到签核输入流）。

## 七、新律四条（已入律库）

* ★**签核基线可复现律**：凡要拿某历史基线当尺子对拍新件，**先证明我方流程能逐位复现该基线**（零差自检），复现不了就不得作尺子。
* ★**复现同源环境律**：复现/对拍须用与归档跑批**同版本** env；环境探活必须测**被调用的那个工具本身**（`klayout -v` 通过 ≠ `run_drc.py` 可跑）。
* ★**对拍两侧同口径归一律**：cell 名随版次变化时，**两侧必须同口径归一化**；只归一化一侧＝造出假差异（会误判"重跑结果与基线全不同"）。
* ★**跑批证据不可跨尝试覆盖律**：多环境/多参数尝试必须各自独立目录与独立日志；失败尝试的日志被后一次覆盖＝证据永久丢失（本口 D2 已踩）。
