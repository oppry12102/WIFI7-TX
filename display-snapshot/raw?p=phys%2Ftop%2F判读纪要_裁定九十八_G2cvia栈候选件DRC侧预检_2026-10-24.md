## 三、结论

* **基准复现**：候选件原样 DRC = **384 条**，与三岛并集基准逐项对拍 **新增 0 / 消失 0**（K04/K05）⇒ 装配链与跑批链口径未漂移。
* **V-M3（栈到 M3）：384 条，新增 0，消失 0**（K06）。
* **V-M5（栈到 M5）：384 条，新增 0，消失 0**（K07）。
  ⇒ **㉕ 的「顶层自建 via 栈」路线，在 DRC 侧对 drv2.outp/outn 两根引脚是干净的**：落焊盘＋垂直 via 栈不产生任何新增 DRC 违例（连到 M5 也干净）。
* **负控有牙**：NC-A 报出 **10 条**新增违例（规则 `M2.a`、`M2.c1`、`M2.d`、`V2.c1`），NC-B 报出 **4 条**（规则 `V1.a`）⇒ 闸门不是恒绿（K08/K09）。
* **零改形**：跑批前后现役四件 sha256/bytes 逐位不变（K10）。

## 四、对待决 ㉕ / ㉘ / ㉙ 的更新

* **㉕**（两条路线二选一）：「顶层自建 via 栈」一侧的几何前提已由**几何模型**升级为**DRC 实证**（两根引脚、到 M5、新增 0）。但**这不构成对 ㉕ 的拍板**——「块内补层级接入焊盘」（b7e7）路线未被否定，两路线代价对比仍属管理员/组员裁量；且本阶段**未做 LVS 腿**（无 pin 层、无顶层网表、网络未定义）⇒ 新件几何对 **LVS 侧**的影响仍未知。
* **㉘**（落焊盘尺寸与起栈层口径）：本阶段实证支持「**1.0µm 落焊盘 + 0.19µm cut + 0.5µm 栅格**」这一组口径在 DRC 侧可行（M2/M3/M4/M5 落焊盘均未触发违例）；**起栈层**实测可行栈一律 **M1 起、经 M2**（与阶段 106 一致）。
* **㉙**（实施授权与跑批次序）：授权与批次**仍待管理员**；本阶段只提供「若实施，几何侧无阻」的前置证据。

## 五、口径边界与缺口（登记，非结论）

1. **走线本体未进本轮 DRC**：本轮只做了「落焊盘＋垂直 via 栈」，**没有**画「落点 → 片边」的片级接入走线（阶段 105/106 量化的 2.518µm 通道）。⇒ 走线本体的 DRC 仍是缺口。
2. **密度规则未补跑**：跑批沿用归档配方 `--no_density`（`M2.j`/`M2.k` 未覆盖）。裁定九十三曾为 CF-A 单独补跑 `--density_only`，本阶段**未做**。
3. **LVS 腿缺席**：新件几何未参与任何 LVS 对拍（无 pin 层、无顶层网表、无网络定义）⇒ 不构成 LVS 通过结论。
4. **仅为两根引脚**：其余 11 根片级接入实例未做候选件 DRC 预检（阶段 106 已判 `mix.nbiasL/nbiasH/drv2.vcc` 为 VIA_BLOCKED、`mix.vcc` 为 VIA_NARROW）。
5. 变体只含 via 栈与落焊盘，**不含** via PCell 实例化（用裸 cut 图形表达）；真实施工应由 PDK via PCell 生成（宽度/间距/包络按 `sg13g2.map` 与 `main_rules.md` 现解析值）。

## 六、自纠记录（据实，三处）

1. **KLayout API 误用**：`Box.left/right/top/bottom` 与 `Point.x/y` 是**属性**不是方法（首版按方法调用 ⇒ `TypeError: 'int' object is not callable`）；`Layout` 无 `shapes()`（须用 `cell.shapes(layer)`）。
2. **坐标系误判**：首版在**块 cell 的局部坐标**里查落点覆盖 ⇒ 一律查不到（K03 假 FAIL）；改用**顶层 cell 展平后**的全局坐标查询 ⇒ 落点覆盖成立、漂移 0。
3. **DRC 跑批偶发无 `full.lyrdb`**：一次跑批只出了 `_sg13g2_maximal.lyrdb` 且「maximum rule set: 0 error(s)」⇒ 引擎被系统负载打断；已加**重试包装（最多 3 次）**并留痕。
