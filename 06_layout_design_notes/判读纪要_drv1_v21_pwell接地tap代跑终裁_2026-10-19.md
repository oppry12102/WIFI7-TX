### 2.1 PDK 源码与真跑实测（两路独立）

实测（我在真 KLayout 里生成 PCell 逐层 dump）：

| 层 | ptap1 本地坐标 | 尺寸 |
|---|---|---|
| Activ 1/0 | `(0,0)-(0.78,0.78)` | 0.78² |
| Cont 6/0 | `(0.14,0.14)/(0.48,0.14)/(0.14,0.48)/(0.48,0.48)` 起 **4 只** | 各 0.16² |

⇒ **tie 中心在本地 (0.39, 0.39)，即「原点 + (0.39,0.39)」；且 tie 只有 0.50×0.60，
不是他在仿真层画的 0.80 见方替身。** 解析式与实测逐位一致（我按 `Cnt_a/b/c`、`M1_c`、`M1_c1` 独立推算
`(0.14,0.09)-(0.64,0.69)`，残差 0）。

### 2.2 后果评估：**轻微，链路仍通**（幸未出事，但属侥幸）

tap 置于 `DTrans(14,100)` / `DTrans(42,100)` 时：

## 四、★ 代跑发现的**三处真 KLayout 不兼容**（他的「双通」断言实际是**单通**）

这是本轮第二个重要产出。`gen_M3_drv1_v21.py` 的注释白纸黑字写着：

> 「⚠ 两个取图助手必须**仿真层与真 KLayout 双通**（v2.0 血训：写死仿真层的 `cell.insts`/`cell.each_shape`

**但真跑连炸三次，每次都是仿真层 API**。他称的「v2.0 血训」修复**未生效**：

| # | 原写法 | 真 KLayout 实况 | 现象 |
|---|---|---|---|
| **①** | `_xy(t)` 取 `t.x/t.y` 否则 `t.dx/dy` | **本构建 `pya.Trans` 既无 `.x/.y` 也无 `.dx/.dy`**（`dir(pya.Trans)` 实测两者皆无），只有 `.disp` | `'Trans' object has no attribute 'dx'` |
| **②** | `bb.hit(x, y)` | `DBox` 只有 `inside/contains/touching/overlaps`，**无 `hit`** | `'DBox' object has no attribute 'hit'` |
| **③** | `_iter_shapes` 只看顶层 | 真跑里 ptap1 的 tie / via_stack 焊盘都在**子 cell（PCell 变体）**内 ⇒ 断言 ② 会**假停线** | `TAP-ASSERT ②：…处没有 M1 接地垫`（假阴性） |

### 4.1 本构建的**正解三件套**（我已跑通，建议直接进 `lib13g2` 真值入口）

```python
it = cell.begin_shapes_rec(layer_index)
it.select_all_cells()          # ① 默认**不进 PCell 变体** —— 不开则 PCell 内部金属一片都看不到
it.each()                      # ② **不能 list()**：实测 list() 反复吐出迭代器自身
while not it.at_end():
    sh = it.shape()
    bb = sh.dbbox() if hasattr(sh, "dbbox") else sh   # ③ shape().dbbox() 给 µm
    d  = it.trans().disp                              #   但 trans().disp 给**整数 dbu**（实测 ptap1@DTrans(14,100) → (14000,100000)）
    out.append(DBox(bb.left + d.x*dbu, bb.bottom + d.y*dbu,
                    bb.right + d.x*dbu, bb.top  + d.y*dbu))
    it.next()
```
实例位移统一读 **`t.disp.x / t.disp.y`**（注：我方 `lib13g2.py:518` 早就在用 `t.trans.disp.x`，**自家库已有正解，
组员那份 helper 反而没沿用**）。
