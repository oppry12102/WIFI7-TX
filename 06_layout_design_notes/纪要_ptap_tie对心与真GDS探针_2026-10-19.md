## 二、为什么要造 GDS 读取器（这不是锦上添花，是补一个洞）

我本机没有 klayout，只有 `pya_b7e7.py` **仿真层** —— 那是我自己写的替身，数值与形状
**由我自己说了算**。于是有一条系统性风险：**自己验自己**。`ptap1` 的 tie 摆在哪儿，
仿真层说什么都只是自说自话；上口我为了「让自检台第⑳项过」垫了一块 0.80 见方 M1，
自检全绿，而真跑的 tie 其实在别处 —— **口径漂移的第四例**。

组长这轮投了 `m3_drv1_v21.gds`（新面锚 `b5b5dce1…` 62350B）。GDSII 记录格式简单，
本机直接解即可，于是有了「真件的第一手几何」这条独立证据链。

**记录格式三个坑（都踩了，记在 `gds_probe` 头部）**：

| # | 坑 | 症状 | 正解 |
|---|----|------|------|
| ① | 记录头是 `[size:2 大端][type:1][datatype:1][data:size−4]`，且 **size = 整条记录的字节数（含 size 字段自身）** | 按「长度不含自身 + 记录号在首字节」的通用写法解 ⇒ 结构名全是乱码、UNITS 出 4.7e+234 | 用 BGNLIB 的 28 字节时间戳块反推帧结构，5115 条记录正好走到 ENDLIB |
| ② | 所有整数/实数**大端** | 坐标解成天文数字 | 4 字节坐标 int32 大端、UNITS 的 8 字节实数大端 |
| ③ | 参照方向记录（STRANS/MAG/ANGLE）的 datatype 常是 **1（bit array）**，不是 5 | 无脑 `_decode` 拿到 bytes，`px*mag` 报「can't multiply sequence by float」 | 按 datatype 分流（4/5 才解成实数） |

**另发现一件要报的事**：这批 GDS 的 `UNITS` 记录解出来是 `8.1658e-09 / 7.9809e-33 m`
—— **非物理**（dbu 若是 7.98e-33 m，任何坐标都离谱）。但顶层 `8/0` 坐标整数范围
`−42150 … 166150`，按 **1nm 栅格**解释正好落在 −42…166µm，与我 gen 的版图尺度吻合 ⇒
**真值取 dbu=0.001µm，UNITS 只作留痕**（`--dbu` 可覆盖）。**这条建议组长侧核一下
GDS 写出端**：若下游有工具真去读 UNITS，会被这个值带偏。

**层号提醒**：顶层自画图形在 GDS 里是 KLayout **内部层号**（235/8/67/50/126/30/10…），
而 PCell 子结构里是 PDK 层号（1/6/8/14/40…）。平铺后统一按 PDK 号读（8=M1、10=M2、
30=M3、50=M4、67=M5、126=TopMetal1、19/29/49/66=各层 via cut），这与我 `lib13g2` 的
映射一致。

## 三、v2.3 的三处变更（金属走线几何零改动）

`dump_shapes --cmp gen_M3_drv1_v22.py gen_M3_drv1_v23.py` 实测：
图形 **201 → 201**，文本 142 → 142，**仅 2 块 M1 替身变化**：

```
仅旧有  (8,0, 13.60, 99.60, 14.40, 100.40)   ← v2.2 自造 0.80 见方替身
仅新有  (8,0, 13.75, 99.70, 14.25, 100.30)   ← v2.3 PDK 真值 0.50×0.60
仅旧有  (8,0, 41.60, 99.60, 42.40, 100.40)
仅新有  (8,0, 41.75, 99.70, 42.25, 100.30)
判定：金属图形零改动 + 无删除文本 → FAIL   ← 预期的 FAIL：这里几何就是要变
```

（那个 `FAIL` 是差分器在**如实报信**：它的判据是「图形零改动」，本轮就是要改这两块。
我不改判据去凑 PASS —— 判据一改，断链测试就废了。）

### ① ptap 实例落点改 `DTrans(_tx−0.39, _ty−0.39)`

**为什么挪 tap 而不是挪 via** —— 两个方案都量过（真 GDS 做基线：删掉两只 ptap1 与两根
`via_stack$3` 后取各层最近邻净距）：

| 方案 | 关键层最近邻净距 | 结论 |
|------|------------------|------|
| **A** 挪 tap (−0.39,−0.39) | Activ 4.48（现状 4.375/4.850）、pSD 4.25、tie 对 M1 6.44 | **各层余量都在 µm 级**（官方 Activ/pSD/M1 间距条款是 0.2~0.5 量级）⇒ 不新增违规 |
| B 挪 via（+0.39,+0.39） | **M4 焊盘对同 x 的 M4 立管只剩 0.085µm**（现状 −0.305 即压着），且要连立管一起挪 | 风险高一个量级 |

⇒ 采纳 A，**与组长建议逐字一致**。修后 tie ⊂ via 焊盘，重叠 **0.3000µm²**（6.5 倍）。

**岛内归属**：v21 已用 LVS 实测证明两只 tap 落在浮空岛内（衬底 `$1` 出现 13→0 次）。
平移量 0.39µm，而四个方向的最近邻 Activ/pSD 净距都在 4.25µm 以上 ⇒ 岛归属不变。
**但这条仍请组长以 v23 的 LVS 复跑盖章**：若 tap 掉出岛，提取网表里 `$1` 会重新出现
（我给的自证判据仍是这一条）。

### ② 仿真层 tie 替身换成 PDK 真值

`_TAP_PDK = {tie:(0.14,0.09,0.64,0.69), tie_c:(0.39,0.39), activ:(0,0,0.78,0.78),
psd:(−0.03,−0.03,0.81,0.81)}`，替身按真值画在 tap 中心。
**只补 tie 不补 Activ/pSD/Cont**：那三层真值虽已量到，但它们是 PDK 内部图形且官方 DRC
已终裁全绿，塞进仿真层只会给 ⑯⑱ 同层间距自查添「合法却报警」的噪声，不增验证价值。

### ③ 取图助手三修（工具层，不涉几何）

- 位移统一收口到 `_disp_um()`：仿真层有 `.dx/.dy`（已是 µm）；真 KLayout
  **既无 `.x/.y` 也无 `.dx/.dy`**，只有 `.disp` 且给**整数 dbu**，要 ×dbu。
- `bb.hit(x,y)` → 纯 Python 包围盒判定（真 KLayout 的 DBox **没有 `hit`**）。
- 取图 → `begin_shapes_rec` + **`select_all_cells()`** + `while not it.at_end()`：
  默认**不进 PCell 变体**（真跑里 tie、via 焊盘都在子 cell 内 ⇒ 旧写法会**假停线**）；
  且**不能 `list(it)`**（实测 list() 反复吐出迭代器自身）。
- 分派判据用 `cell.insts`（仿真层私有属性），**不用 `hasattr(begin_shapes_rec)`** ——
  我自己的仿真层也实现了同名方法（当生成器用），照 hasattr 分派会先在本机炸。

**按 v1.7 增补自报**：以上 API 修法来自组长实测正解，我这边只做了**仿真层自证 +
真 GDS 几何交叉验证**，**API 本身未经真跑背书，按未验证计**，请复跑时留意这三处。

## 四、全库 tie 覆盖率审计（真 GDS 第一手）

`gds_probe --tap-ties`：对每个 `ptap1` 实例算 tie 世界框，在**去掉全部 ptap1** 的平铺
几何里找与它重叠最多的 `8/0`，算覆盖率。

| GDS | ptap 只数 | 最低覆盖 | 判读 |
|-----|-----------|----------|------|
| `m3_drv1_v20.gds`（旧面基准） | 0 | — | 本来就没有 tap |
| `m3_drv1_v21.gds`（新面锚） | 2 | **15.40%**（0.0462/0.3000） | ⚠ 压一角 |
| `m3_drv2_v18.gds` / `m3_drv2_v20.gds` | 8 / 8 | **100.00%** | ✓ 全覆盖 |
| `m2_mix_v27.gds` / `m2_mix_v31.gds` | 8 / 8 | **100.00%** | ✓ 全覆盖 |

**结论：缺陷是 drv1 独有的**，因为 drv2/mix 的 tap 摆在**自画 M1 护环中心线**上，
环宽 ≫ tie ⇒ 整个盖住；drv1 没有环，只能靠 via 焊盘，而 via 又打在实例原点。
⇒ **drv2 v22 / mix v32 本轮零改动**（不是「查过没问题」，是「量过且已记录」）。
