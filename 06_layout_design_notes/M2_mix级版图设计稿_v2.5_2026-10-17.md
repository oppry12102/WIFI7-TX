## 1. 15 处 FAIL 的病根：npn13G2 的 C/B/E **同 x**

实测（`inspect.py` 取 PCell 真实引脚）：

| 器件 | C | B | E |
|---|---|---|---|
| npn13G2（任意 Nx） | y **+1.13** | y **−1.14** | y **−0.01**（居中） |

**C/B/E 全在同一个 x**。于是：只要某条网的竖直干路还走在这个 x 上，它必然竖穿同器件
的另外两只脚 —— 轻则过孔柱压住异网金属（⑤d），重则 M1/M2 直接短接（⑤c）。
**v2.2 的 15 处 FAIL 无一例外全是这一类**，所以本版不逐个打补丁，而是给三类脚
各划一条专属通道。

| 脚 | 原走法（v2.2） | v2.3 走法 | 通道 |
|---|---|---|---|
| 集电极 C | 竖轨直接走器件 x（∓9.975） | M1 上**向外**折，再上竖轨 | x = ∓15 |
| 基极 B | 过孔柱**直接压在 B 脚上** | M1 上**向岛心**内折，再上竖管 | x = ∓3 / ±6（四条立管四条通道）|
| 发射极 E | M2 竖线走器件 x | 保持不动（本来就在 M2 上） | — |

三条通道互不同 x；C/B 的插头都在 **M1**，E 的干路在 **M2** → 层与 x 双重错开。
柱头只落在自己的通道上，通道里 M2/M3/M4/M5 全空。

## 2. 三处结构性 bug（返工时挖出）

### 勘误 ②：Rd1/Rd2 两端接反（**电气错**）

网表：`Rd1 lop lopd 10` → **P1 = lop、P2 = lopd**。
v2.2 把 lopd 的 M3 立管接在 **P1**、把 `'lop'` 标注画在 **P2** 的 M1 短脚上
—— 版图上叫 "lop" 的那条网其实是网表的 lopd。

**为什么没人看见**（这才是要点）：

- 第 ⑦ 项「引脚↔网名」比的是 `DEV_NETS` **声明**，而声明是对的（比的是声明不是版图）；
- `NET_DECL` 只比**网名集合**，不比「哪个脚」，`lop=[(Rd1,P2)]` 与集合口径自洽；
- ⑤b 同名分裂看的是连通；⑤c 跨层短路看的是短路 —— 都管不了「接到了另一条网的脚上」。

处置：改正极性（P2→lopd 立管、P1→lop 下引），`NET_DECL` 同步改正；
并新增自检台**第 ⑫ 项「引脚极性（几何取证）」**：拿 PCell 真实引脚坐标 +
过孔感知连通分量，直接验「网表给这个脚的网名」是否真的在这一脚的连通分量上。
它当场复现了本 bug，也当场抓出了我在 v2.3 首版里改漏的一处（见 §4）。

### 勘误 ③：`RB_H` 算式套错 → nbiasH/nbiasL 够不到竖条（**电气断**）

```python
RB_H = 0.72 + 0.84 * RG.res_params(2000, "rhigh")["_geom"][0]   # v2.2
```

`_geom[0]` **已经是算式求出的长度**（112.69µm），再套一次 `0.72+0.84·L` 得 95.38；
而 PCell 的真实 P2 高度是 `0.72 + 0.84·133.3 = 112.69`。

后果：nbiasH/nbiasL 的 TOPM1/TOPM2 立管从 y=330.38（**电阻腰上**）起，
永远够不到 P2 引脚 y=347.692 —— 两条偏置网在版图上是断的。
⑤b 看不见（同一条网只标了一个名字，无标注的另一截隐形），⑫ 看得见。

处置：全岛一律用 `res.p["P2"][1]` 真引脚 y，不再用算式推。顺带修好
`NIF_Y`（原来也是 `IF_Y + RB_H + 14`）。

### 勘误 ⑤：guard 环几何骑在核内容上（**潜在真短**）

```python
RING_M = 6.0                       # 环到核边界
ring_w = 4.0
for (ly_name, inset) in (("M1", 0.0), ("M2", ring_w + 1.0)):   # M2 环 inset=5
```

M2 环落在 `x∈[CORE_X0−1, CORE_X0+3]`，而 CORE bbox **正是由最外侧那只器件定义的**
→ M2 环必然压在最外侧器件上。实测两处真碰：Rb1 的 M1→M3 柱脚整个踩在 M2 环上；
XBI2 的 nvtop 柱差 0.05µm 压上。

处置：环宽收到 2µm、`RING_M` 提到 8µm，M1 环贴 guard 边、M2 环嵌其内侧 1µm，
两环都退到核外 ≥3µm。岛宽 143.4 → 143.4µm（高 379.9 → 383.8µm）。
岛框从「环骑内容」变成「环在外、离核 3µm」。

## 4. 自检台第 ⑫ 项：引脚极性（几何取证）

```python
# netaudit.audit_pin_nets()
#   网表 pin 次序 → 每个脚的连通分量上的实际网名集合
```

不是比声明，是比**几何**：拿 PCell 实例的真实引脚坐标、在**该脚自己的金属层**上
取连通簇，再用**过孔感知的并查集**求电气连通分量，看网名在不在里面。
两个判据：

- 分量上**没有**该网名 → 接错脚 / 断线；
- 该脚所在层**没有金属** → 悬空脚。

**它当场抓出了我在 v2.3 首版里改漏的一处**：重写 gm 基极段时把竖条**底端**的
`climb(rx, RB_Y-1.2, …)` 漏掉了 → `Rba1.P1 所在连通分量「无标注」`（底端没接上 na1p）。
补回即 PASS。这条注入已进 `teeth_v11.py`（注入 9）。

### A1 六只 cmim 的落位改为「库解 W/L + 端子锚定」
- **W/L 交给库**：`Board.mim_cap(name, C_fF, target)` 按官方密度 `cmim_caspec=1.5 fF/µm²`

  `n=fix((w+0.12)/1.26)`、`xoffset=(w−(n·1.26−0.12))/2` 须落 0.005 网格；
  23.665 → 内部 Vmim 阵列 offgrid×1296、23.66 干净）。我在 v2.5 手算的 23.66 恰好
  落在干净相位，但相位规则应由库持有，不该在交付件里复刻。
- **锚定不变**：两端引脚（`Metal5.pin(67/2)` 与 `TopMetal1.pin(126/2)`，每层 1 枚、同心）

  （端子 y = 180/180/206/206，端子 x = 偏置通道 x / rfop·rfon 通道 x）一字不改。
- **先量后摆**：插入前先造一只同名 cell 量出「bbox 中心 − 引脚中心」真实偏移；若将来
  两者分离，用目标点反推 bbox 中心落点 —— 精确落位，且不留错位实例。落位后用 `Dev.p`
  自证端子坐标，偏差 > 1nm 即占位回落（不猜）。
- 口径勘误（组长 ②）：pin shape 的 datatype 是 **/2（pin purpose）**，**/1 是网名 label
  层（METAL_LNUM）**。本件一直按 `/2` 取脚（`Board.pin_centers` = DT_PIN），口径本就正确。
- 仿真层仍走占位（`hasattr(pya,"WARN")` 短路）⇒ 自检台第 ⑦b 项照旧核对 6 个占位件声明。

### A2 顶层柱的 TopVia1 档位钉 1×1（几何与 v2.5 逐位相同）
- lib v2.2 起 `Board.via(t_layer="TopMetal1")` 的 **vt1 阵列档位继承 cols/rows**
  （v2.1 及更早硬编码 1×1）。本件 §7 的 rfop/rfon 顶层柱默认 cols=2,rows=2 ⇒ 会静默
  变成 2×2 阵列，而 TM1 平台**非线性**（实测 1×1 = 1.64 见方、3×2 = 2.94×2.10；

### C2 附录用的话：为什么「任意两条平行边 < minw」是错的
先按那个口径写过一版，drv1 的 vcc 直角拐角（两条**同侧**平行边相距 1.18µm）假报 1 条；
官方对那一处**不报**。同侧 = 材料不在两条边中间 ⇒ 是台阶不是窄腰。改成**相向**后为 0。
另：形态学开运算（W×W 正方）那套把官方报的这些判成**合格**，与 deck 口径不符 ⇒ 只留作对照打印。

`CHANGELOG_2026-10-17_Q10.md` §3。
